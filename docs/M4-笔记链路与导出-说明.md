# M4 笔记：链路打通与导出（0.7.0-M4 / versionCode 13）

> 版本：`0.7.0-M4`（versionCode 13）· 真机已验证 · 2026-11-15 14:35

## 一、结论：M4 的骨架早已存在，缺的是验收通道

设计目标 M4 = 「分块摘要 + Markdown 导出 + 设置页」，验收 = 「课后 1 次点击产出可读笔记；模型管理可切换」。

对完代码，这三件的骨架在 M2.6/M2.7/M2.8 就已经写好了。M4 真正缺的不是开发，而是**验收通道**——而通道被一个结构性障碍卡住了：

| 路径 | 库里有场次 | 能出笔记 |
|---|---|---|
| 真实录音 | 有 | 能 |
| WAV 回放 | 有 | 能 |
| **文本回放（经济学课）** | **没有** | **不能** |

回归测试已统一到经济学课语料，而那堂课的 WAV 已按「不留音频」策略删除。于是「只用经济学课验证」和「验证笔记」直接冲突。本轮第一件事就是拆掉这个冲突。

## 二、M4.1 文本回放改成走真实链路

不再「只往界面塞字幕」，而是按真实录音的顺序跑：

```
建场次(status='recording')  →  逐条落库(每句单独提交)  →  每满 8 句触发一次云端增量
        →  结束把场次改 done  →  startPostprocess() 走正式出稿
```

这样一节经济学课同时验证了三件事：增量能不能跑、出稿能不能出、笔记可不可读。

代价是主库会多一条 `replay_eco_*` 开头的场次（标题带时间戳，便于和真实课堂区分）。

## 三、M4.2 笔记质量：根因是那个哈希 bug，不是提示词

修复前那份（session 45）标题是「然准时针时间的短」「的消费中所得到的效用增加」，因为增量全超时 + 出稿降级成抽取式。

修完 `core/src/tokenizer.c` 的 pair 哈希后，同一堂课现在长这样：

```
## [00:01] 供给概念与影响因素
> 供给的定义：特定时期给定价格下生产者愿意并能够提供的商品数量
  影响因素包括价格、生产目标、技术水平、成本、相关商品价格、预期与政策

## [03:53] 吉芬商品与生产要素
> 价格上涨使购买力骤降收入效应占优
  生产要素包括劳动资本土地与企业家才能
```

11 章，每章两行摘要，标题全部可读。**不需要再改提示词。**

### 增量与分章的分工

实测发现两条路径各有短板：

| 路径 | 章节数 | 摘要 | 正文文本 | 耗时 |
|---|---|---|---|---|
| 会中增量定稿 | **2 章**（4 分钟课） | 第 2 章重复第 1 章 | **纠错后**（「市场价格是指政府为了维维持一一品品的产产」→「支持价格是指政府为了维持某种产品的生产…」） | 17 ms 本地合并 |
| 语义分章 | **11 章** | 各章独立 | 原始 ASR | 约 2.8 s |

所以改成：**增量只负责「实时纠错 + 会中进度」，出稿统一走语义分章**。
为了不让纠错白做，`core/src/note.c` 的取文本优先级改为：

```
text_refined（增量纠错） > text_corrected（课后声学校正） > segments.text（原始 ASR）
```

实现方式是 `load_segments` 的 SQL 加 `LEFT JOIN text_refined` 选 6 列，
`seg_text()` 按 0 基列号读第 5 / 4 / 3 列依次回退。

## 四、M4.3 笔记导出（原来导出按钮导的是 WAV）

「导出」按钮原本只导录音文件，笔记拿不出来。现在：

- 点「笔记」打开弹窗，底部多一个 **「导出到下载」**
- 落到 `下载/ClassMate/notes_*.md`，可用数据线直接拷到电脑
- `RecordingStore.exportAs(context, file, mime)` 是新增的通用导出，WAV 与 md 共用一条 MediaStore 通道

**踩坑**：mime 用 `text/plain` 时，MediaStore 会把 `.md` 规范化成 `.md.txt`；必须用 `text/markdown` 才保住扩展名。

## 五、M4.5 会中增量：从「4 批全超时」到「5 批全成功」

同一堂课、同样的批数：

```
修复前  rolling seq=1..4  → 全部 timeout（会中增量待重试 seq=1(timeout) ×4）
修复后  rolling seq=1  segs=8  cost=2964ms  summaryLen=187
        rolling seq=2  segs=8  cost=2073ms  summaryLen=188
        rolling seq=3  segs=8  cost=2638ms  summaryLen=202
        rolling seq=4  segs=8  cost=1921ms  summaryLen=164
        rolling seq=5  segs=1  cost=1317ms  summaryLen=182   ← 尾批补齐，tail=ok
```

每批 `reasoning_len=0`（思考已关）、输入 token 恒定在 480–670（只发新增段落，不重发全文）。

## 六、顺手修的一处数据卫生问题

增量摘要靠 `status='recording'` 定位当前场次。之前测试遗留了一条 14:05 的场次一直是 `recording`，实测出现**纠错数据写到了旧场次名下**（`text_refined` 里 8 条落到两天前的场次）。

现在 App 启动时会把所有 `status='recording' AND ended_at=0` 的场次收敛为 `done`——因为进程刚启动时不可能有录音在跑，这些必然是崩溃/被杀的遗留。

```
ClassMate/Post: cleanup stale recording sessions: 1
```

## 九、这轮没做的

- **本地模型（1.1 GB Qwen）**：暂不纳入。云端 2.8 秒出稿已够用，本地模型留到 M5 打磨阶段再定。
- **M4.2 的课堂提问内容**：不纳入本轮笔记。
- **内录端到端**：仍卡在「必须人工点系统授权框 + 必须真实播放声音」。验证方法是放一段 3–5 分钟网课，选「媒体音频」，看字幕跟不跟得上、视频里说套话会不会出答案。
- **原文行里的 ASR 错字**（「古建商农」「积分商品」）：增量只纠它注意到的句子，不是每句都纠。要彻底解决得靠课后二次校正模型（SenseVoice），属于可选优化。
